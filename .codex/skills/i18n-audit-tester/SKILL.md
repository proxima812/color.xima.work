# i18n Audit Tester

Используй этот скилл, когда нужно проверить или исправить полноту переводов в `src/i18n`.

## Workflow

1. Запусти аудит:
   `node .codex/skills/i18n-audit-tester/scripts/audit-i18n.mjs`
2. Если есть `missingInLocales`, добавь недостающие ключи во все нужные `src/i18n/locales/*.ts`.
3. Если есть `missingUsedKeys`, добавь ключи, которые реально используются в компонентах/страницах.
4. Для новых значений:
   - сохраняй стиль существующего locale-файла;
   - не меняй уже существующие переводы без явной причины;
   - держи UI-тексты короткими и полезными для gradient gallery;
   - если точный перевод неочевиден, добавь лучший короткий вариант и явно упомяни риск.
5. После правок повтори аудит. Он должен вернуть нули по missing-блокам.

## Rules

- Источник ключей: реальные locale-файлы в `src/i18n/locales` плюс вызовы `t("...")`.
- Локали проекта: `en`, `ru`, `es`, `zh`, `tt`, `kk`, `uk`.
- Ключи именуй по зоне: `nav.*`, `menu.*`, `home.*`, `colors.*`, `filters.*`, `card.*`, `footer.*`, `copy.*`, `theme.*`.
- Не делай массовый рефакторинг i18n-структуры ради аудита.
- Не добавляй машинный перевод пачкой, если контекст спорный.
- Если нужно добавить новый UI-текст, сначала добавь ключ во все locale-файлы, затем используй `t("key")` в компоненте.

## Script Notes

Скрипт читает:

- `src/i18n/locales/*.ts`
- `src/**/*.{astro,ts,tsx,js,jsx,svelte,vue}`

Он проверяет:

- ключи, отсутствующие в отдельных locale-файлах;
- ключи, используемые в коде, но отсутствующие в словарях;
- ключи в словарях, которые не найдены в коде.

`unusedLocaleKeys` не всегда ошибка: SEO, будущие страницы и динамические ключи могут быть валидными.
